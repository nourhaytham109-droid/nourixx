# Nourix POS

نظام كاشير عربي يعمل عبر Node.js ومحرك PostgreSQL مدمج. تُحفظ قاعدة البيانات وبيانات المطعم والصور محليًا على الجهاز، دون الحاجة إلى إعداد خادم قاعدة بيانات منفصل أو الاتصال بالإنترنت.

الاسم التجاري للتطبيق هو Nourix، مع شعار ورسمة خلفية طعام محليين داخل مجلد `assets`.

## المتطلبات

- Node.js 20 أو أحدث
- لإنشاء مُثبّت Windows NSIS من المصدر: Windows أو Linux x64 مع Node.js 20 أو أحدث.
- بيئات Linux بمعمارية ARM64 يمكنها إنشاء حزمة التثبيت المحمولة المذكورة أدناه، لكن هدف NSIS في electron-builder لا يعمل بهذه المعمارية.

## تثبيت Windows

يمكن إنشاء مُثبّت Windows x64 من مجلد المشروع على Windows أو Linux x64 بالأوامر التالية:

1. `npm install`
2. `npm run build:win`
3. شغّل `release/Nourix-Setup-1.0.0-x64.exe`.

يفتح المُثبّت تطبيق سطح مكتب Nourix ويضيف اختصارًا لسطح المكتب وقائمة ابدأ. تُحفظ قاعدة البيانات والإعدادات والصور محليًا في مجلد بيانات التطبيق الخاص بالمستخدم، ولا تُحذف عند إزالة البرنامج. لإنشاء نسخة Windows غير مثبتة للاختبار، استخدم `npm run build:win:dir`.

### حزمة تثبيت يدوية لنظام Windows

إذا لم تتوفر أداة NSIS على بيئة البناء، أنشئ حزمة ZIP قابلة للتثبيت بعد بناء ملفات Windows:

1. `npm run build:win:dir`
2. `npm run package:win:install-kit`
3. فك ضغط `release/Nourix-Setup-Windows-1.0.0.zip` على Windows.
4. شغّل `Setup.bat` من المجلد المستخرج. ينسخ البرنامج إلى مجلد برامج المستخدم، وينشئ اختصارين لقائمة ابدأ وسطح المكتب، ثم يشغّل Nourix POS.

تتضمن الحزمة سكربت إزالة تثبيت يحذف ملفات البرنامج والاختصارات فقط، ويُبقي بيانات المطعم والنسخ الاحتياطية. حزمة ZIP ليست ملف NSIS تنفيذيًا منفردًا؛ يجب استخراجها أولًا ثم تشغيل `Setup.bat`.

## التشغيل لأول مرة

1. انسخ `.env.example` إلى `.env`.
2. ثبّت حزم المشروع: `npm install`.
3. أنشئ الجداول والأصناف الابتدائية: `npm run db:migrate`.
4. شغّل التطبيق: `npm start`، ثم افتح `http://localhost:3000`.

عند التشغيل لأول مرة، تظهر شاشة لإدخال اسم المطعم وأرقام الهاتف وإنشاء حساب المدير الأول. عنوان المطعم وشعاره اختياريان، ويمكن إضافتهما في هذه الخطوة أو لاحقًا من صفحة **الإعدادات**؛ ويظهران على الإيصال عند إضافتهما. تُحفظ بيانات المطعم في `restaurant.json` والصور في مجلد البيانات المحلي مع قاعدة بيانات المطعم على هذا الجهاز. الإعداد الافتراضي يستخدم مجلد المستخدم المحلي (`%LOCALAPPDATA%/Nourix/data` في Windows، و`~/Library/Application Support/Nourix/data` في macOS، و`~/.local/share/Nourix/data` في Linux). لتحديد مكان مختلف، اضبط `NOURIX_DATA_DIR`؛ ويظل `DATA_DIR` مدعومًا للتوافق مع الإعدادات السابقة. تثبيت كل مطعم على جهازه ينشئ قاعدة وملف إعدادات منفصلين، ولا تتم مشاركة البيانات بين الأجهزة. ينشئ البرنامج نسخة احتياطية تلقائية يوميًا محليًا بجوار مجلد بيانات التطبيق ويحتفظ بآخر 14 نسخة بصيغة `.nourix`، وتشمل قاعدة البيانات وإعدادات المطعم وصور الأصناف والشعار. يمكن للمدير إنشاء نسخة يدويًا أو تنزيلها أو اختيار نسخة لاستعادتها من صفحة **الإعدادات**. قبل الاستعادة تُحفظ نسخة أمان من البيانات الحالية، ويُطلب إعادة تشغيل البرنامج لإتمامها؛ ويصبح البرنامج مؤقتًا للقراءة فقط بعد تجهيز الاستعادة.

يمكن تغيير بيانات المطعم وعرض ورق الإيصال من صفحة **الإعدادات**. على Windows، اختر طابعة الكاشير من قائمة الطابعات المثبتة، ويمكن تفعيل طابعة ثانية (مثل طابعة المطبخ) لإرسال نسخة الإيصال إليها بالتزامن؛ لا تظهر نافذة المتصفح عند الطباعة. يلزم تثبيت الطابعتين وتعريفهما في Windows. لا تتوفر الطباعة المباشرة متعددة الطابعات على Linux أو macOS حاليًا. بعد تسجيل الدخول يستطيع المدير إضافة حسابات مدير أو كاشير من صفحة **المستخدمون**.

## الوظائف

- نقطة بيع للتيك أوي والدليفري والحجز، مع تبويبات لمسودات طلبات متعددة مستقلة. تحفظ كل مسودة سلتها ونوعها وبيانات عميلها وملاحظاتها وطريقة دفعها.
- زر «تأكيد الطلب وطباعة» هو وسيلة التأكيد الوحيدة: يسجل الطلب ثم يرسل ملف الإيصال مباشرة إلى طابعة الكاشير والطابعة الثانية بالتزامن عند تفعيلها. بعد التأكيد تُمسح بيانات العميل والملاحظات والسلة استعدادًا للطلب التالي، وتظهر رسالة برقم الطلب لمدة ثانيتين. يبدأ ترقيم الطلبات من 1 مع كل وردية جديدة. لا تتضمن قائمة إجراءات الطلبات زر طباعة.
- لكل صنف أحجام صغير ووسط وكبير بأسعار مستقلة يحددها المدير، وتُحفظ قيمة الحجم المختار في الطلب. الكميات تخص الصنف وتُشارك بين أحجامه.
- ملاحظات الطلب ووسيلة الدفع (نقدي، محفظة كاش، فيزا)، ورسوم توصيل من 10 إلى 50 جنيهًا بزيادات 5 جنيهات أو قيمة مخصصة. تظهر العناوين المسجلة مع رسومها وتُستعاد تلقائيًا عند اختيارها.
- لا تُضاف ضريبة على الطلبات؛ الإجمالي هو قيمة الأصناف ورسوم التوصيل فقط.
- تعرض صفحة الطلبات رقمًا مختصرًا وبحثًا برقم الطلب أو هاتف العميل، مع تفاصيل قابلة للفتح. تتيح الإجراءات إنهاء طلبات التيك أوي بزر «تم التسليم»، وإسناد الدليفري والحجز إلى سائق. ينتقل الطلب المسند إلى «في الطريق»، ثم يكتمل تلقائيًا بعد 30 دقيقة ويختفي من صفحة الطلبات بعد 10 دقائق إضافية؛ ويمكن إلغاء إسناد السائق النشط لإعادة الطلب إلى «قيد التحضير».
- صفحة «تقرير الطلبات» تعرض طلبات الشهر التقويمي الحالي بجدول التفاصيل نفسه دون قائمة إجراءات، مع البحث برقم الطلب أو الهاتف وفلاتر نوع الطلب ووسيلة الدفع والحالة. لا تُطبّق فترة التاريخ والوقت إلا بعد اختيار البداية والنهاية والضغط على «تطبيق الفلاتر»؛ ويوجد زر لمسح الفلاتر وإظهار كل طلبات الشهر مجددًا. الطلبات من الشهور السابقة تختفي من هذا التقرير فقط وتبقى محفوظة في قاعدة البيانات.
- الأرقام معروضة بالأرقام الإنجليزية، مع وضع ليلي ونهاري يمكن التبديل بينهما ويحفظ اختيار المستخدم.
- لا يتطلب الحجز تاريخًا أو موعدًا مسبقًا؛ يُسجل بتاريخ ووقت إنشاء الطلب كالمعتاد.
- صفحة المنيو لإدارة فئات الأصناف (إضافة وتعديل وحذف) والأصناف وأسعار الأحجام والصور وحالة ظهورها في نقطة البيع. يجب اختيار فئة مسجلة عند إضافة أو تعديل صنف، ولا يمكن حذف فئة مرتبطة بأصناف حتى تُنقل الأصناف إلى فئة أخرى. لا يتتبع التطبيق كميات مخزون.
- صفحات الطلبات والتقارير والمصاريف والمنيو والعملاء. ابحث عن العميل بالهاتف لعرض بياناته وعناوينه وسجل طلباته وقيمتها.
- تعرض صفحة المصاريف مصاريف الوردية النشطة فقط؛ عند إقفال الوردية تبقى مصروفاتها محفوظة وتظهر ضمن زر «المصاريف القديمة» مع التاريخ والوقت والبحث بالوصف.
- للمدير زر إنهاء الوردية وصفحة سجل الورديات. بعد تأكيد الإقفال يُطبع ملخص الوردية على طابعة الكاشير والطابعة الثانية عند تفعيلها، ويمكن إعادة المحاولة من سجل الورديات إذا تعذرت الطباعة. يطلب النظام من كل كاشير تسجيل عهدة الدرج عند تسجيل الدخول، ويظهر عند الإقفال إجمالي المبيعات وطرق الدفع والمصروفات والعهدة، بالإضافة إلى صافي الوردية المحسوب بطرح المصاريف والطلبات الملغاة من إجمالي المبيعات. بعد الإقفال تُسجل وردية جديدة تلقائيًا.
- إدارة أصناف المنيو وحسابات الدخول متاحة للمدير فقط. يستطيع المدير تعديل اسم الدخول والصلاحية وحالة الحساب وكلمة المرور، ويستخدم النظام اسم الدخول بدلًا من الاسم الشخصي.
- يحدد المدير صفحات الوصول لكل حساب كاشير من نموذج المستخدمين؛ تُخفى الصفحات غير المختارة ويُرفض الوصول إليها من واجهات الخادم أيضًا. صلاحيات المستخدمين والدليفري وإدارة المنيو تبقى للمدير فقط، بينما يمتلك المدير جميع الصفحات تلقائيًا.
- تعرض لوحة سائقي التوصيل لكل سائق عدد الطلبات المسندة إليه، والمبلغ المستحق للمطعم محسوبًا من المجاميع الفرعية للطلبات غير الملغاة، ومستحقات السائق محسوبة من رسوم التوصيل لا من عمولة. يمكن تسجيل المبالغ المحصّلة من المطعم جزئيًا، وتعرض اللوحة الرصيد المتبقي، كما تتيح عرض تفاصيل الطلبات المسندة للقراءة فقط.
- صفحة سائقي التوصيل متاحة للمدير لإضافة السائقين وتعديل أسمائهم وأرقام هواتفهم، مع التحقق من عدم تكرار رقم الهاتف.
- تعرض شاشة الدخول قائمة منسدلة بحسابات الدخول النشطة للاختيار.

## دليل البرنامج

راجع [دليل Nourix POS ومميزات النظام](./docs/nourix-pos-guide-ar.pdf) للتعرف على الإعداد الأول، وإنشاء الطلبات، وإدارة العملاء والمنيو والورديات والتقارير والنسخ الاحتياطي. يتوفر مصدر الدليل القابل للتعديل بصيغة [HTML](./docs/nourix-pos-guide-ar.html).

## إعداد النشر

- لا تشارك مجلد `data`؛ فهو يحتوي على قاعدة بيانات المطعم.
- في الإنتاج فعّل HTTPS واضبط `COOKIE_SECURE=true`. إذا كان التطبيق خلف وكيل HTTPS موثوق، اضبط `TRUST_PROXY=true`.
- يمكن للمدير إدارة النسخ الاحتياطية من صفحة الإعدادات؛ النسخ محلية على الجهاز ولا تُرفع إلى خدمة سحابية. بيانات دخول الجلسة محفوظة في ملف تعريف ارتباط `HttpOnly`، وكلمات المرور مخزنة باستخدام scrypt.
